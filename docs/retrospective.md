◎ とても良い　○ 良い（少し足すともっと良い）　△ 直すと良い

- ◎ **操作の不満を、困る場面ごとに具体的に**（11/21）。「説明が長いとページの配置が変わってカーソルが外れ、ガタガタする。まともにプレイできない」「置いた直後はクリックしてもレシピを選べない」。どれもその日に直せた。

- ◎ **絵の感想を短く、理由つきで**（11/21）。「魔力炉は動いていないとき中の結晶がない方が良い」「左が0区2区4区6区はそんな数え方するか？」。
- ◎ **部の呼び方とフェーズの切り方を整理し直した**（11/21）。「6区で第1部が終わって、7区1個で第2部が終わってる？」と気付き、検証のフェーズ16も自分から足した。
- ◎ **見直しの形を決めた**（11/21）。「量を増やすだけでなく、レンズのように別レシピも併用したい。別の機械なら副産物や大きさの差が要りそう」。
- ◎ **図面を送り、「できないようにしろという意図ではない」と添えた**（11/21）。AIが依頼の量を上げる案を出せた。
- ○ **「区2の枠って40のはず。どこかで計算ずれてそう？」**（11/21）。良い指摘だった。お手本の前提（区0が改善前）をAIが先に書いていれば、迷わなかった（AIの側の問題）。

## 人と AI の役割

- **人が強かったところ：** 遊んで分かる不満（ガタガタ・瓦礫を開けても戻らない）、仕組みの決め方の案（瓦礫はあとの区画で、見直しは別レシピで）、全体の切り方（部の呼び方・検証のフェーズ）、AIのお手本を大きく超える配置を組むこと。
- **AI が強かったところ：** シミュレーションとお手本の配置で、16区画の収支と詰まりを毎回確かめること、中身の表と下書き、ドット絵、町の地図の絵、計画のメモと企画まとめの書き足し。
- **AI が弱かったところ：** 遊ぶ人がどこまで工夫するかを見積もること（依頼の量）、中身が増えたときの画面全体のまとまり（タブ・図鑑）を自分から見直すこと。

## 次のゲームで使う手順

前作の16の手順に、今回の教訓を足した（17〜20）。

1. 好きなゲームの面白さを抜き出し、別のチャットで企画を固める。企画まとめ（Docs）を「正」にして、作るチャットにはリンクを渡す。
2. 企画に「変えないこと」と「ジャンルのお約束」を書く。
3. 中身の全体の形を表で決める。
4. 名前と見た目の方向を早めに決める。
5. フェーズは「中身を足す」「見た目」「最終の調整」を分ける。1フェーズは1〜2日で終わる大きさに。
6. フェーズごとに遊んで、番号と理由で答える。決まったことは計画のメモと企画まとめの両方に。
7. 「忘れないようにメモ」は Issue にし、マイルストーンを付ける。AI はフェーズを閉じる前に残りの Issue を並べる。
8. 大量に作るものは、人が見て直せる表やアーティファクトにする。試し描き・試作を数個見せてから量産する。
9. 調整の前提を決めてから、最後にまとめて合わせ、固定する。固定した数字はテストで守る。
10. 調整のあとに足すものは、「難易度を変えるか」を先に決める。
11. 操作の不満は小さくても、すぐ言う。
12. 長い計算は、締め切りと「寝る前にどこまで」を書く。
13. （パズル）素材や部品ごとに「いちばん素直な部品では、なぜだめか」を企画で1行書き、早めに確かめる。
14. （パズル）ソルバーの限界を最初に測り、大きさの上限をそこから決める。
15. （生成）量産の前に、計算の目安と人の順位が合うかを数問で確かめる。
16. （生成）「同梱するだけ」か「その場で作る」かを先に決める。
17. **（工場・配置）新しい仕組みは、本編の前に試作の区画で1つずつ遊ぶ。中身の表の段階で、新しい仕組みの区画にお手本を1つ置いて広さを決める。**
18. **（調整）依頼や目標の量は、工夫する人の配置で決める。** 配置を文字列で渡せる仕組みを早めに入れ、人の配置をもらって量を測り、テストに入れる。
19. **（調整）お手本の前提（最初の形か、改善した形か）を書き、報告で言う。** 人の計算とずれたら、まず前提を比べる。
20. **（画面）中身を足すフェーズの終わりに、全ページ（タブ・図鑑・説明・地図）を見る。** 新しい道具や素材は、図鑑とマウスの説明を同じコミットで足す。分け方（タブ）は、最後の中身の数で決め直す。

### 頼むときのひな形（今回の分を足した）

```
■目的：何を作る・直すか
■正の文書：企画まとめのリンク（決まったことはここに書き足す）
■変えないこと：遊びの柱、ジャンルのお約束、固定した数字 など
■前提：試すときの条件、遊び方（ふつうの人／工夫する人）、お手本は最初の形か改善した形か
■目標：数字と、その測り方（何を相手に、何回測るか）
■素材・部品の役目：それぞれ「いちばん素直な部品ではできないこと」
■大きさの上限：ソルバーやヒントが間に合う範囲、区画の広さはお手本で確かめる
■人の配置：送った図面はテストに入れ、量の目安にする
■任せてよいこと：数値の当てはめ、生成、テスト、絵
■必ず確認してほしいこと：遊びの柱にかかわる変更、全体に効く値の変更、2通りに読める指示
■人が遊ぶ回数：試作は○回まで、1回○問
■残っているメモ：Issue 番号（フェーズの終わりに読み上げる）
■報告に入れてほしいこと：足した機能の場所、お手本の前提、全ページの確認結果、作れなかったもの
■締め切り：日本時間 ○月○日 ○時
■説明：やさしい日本語で、結論から
```

## 残っていること

- フェーズ16（検証）：素材の搬出を自由にした場合（倉庫の出す口を、どの原料でも・どこにでも・いくつでも置ける）、1枚の盤面で飛空艇まで作るのに要る広さ
- 区8・区13の依頼は、人が全部同時に満たせる量のまま（順に増える形なので、そのままにした）
- 区11は胞子が毎分30までなので、依頼を上げられない（区12の量の基準になっている）
- 枠の別レシピ（プレス機・焼き入れ鋼から）と帆布の別レシピ（澱で糊づけ）は、お手本では使っていない（見直しに使う想定）
- 遊んだ人からのフィードバック（全系統版の公開のあと）
