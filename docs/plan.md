## 変えないこと

遊びの柱と、工場ゲームのお約束。変えたくなったら、必ず人に確かめる。

- 根幹：新しい何かを開きたいから工場を作り、改善する
- 芯：限られた区画に、機械とベルトを詰め込む
- 看板：範囲がベルト上の素材にも効く（通り道がレシピになる）
- 戦闘なし、移動なし（分身も手作業もない）、資源探しなし（資源は倉庫から）
- 置いたらすぐ建つ。壊す・動かすは何度でもタダ（素材は戻る）
- 同じ配置なら必ず同じ結果
- ベルトには向きがあり、分けたり合わせたりできる
- 機械には入口と出口があり、詰まったら止まる（物は消えない）
- 毎分いくつ流れているかが見える。範囲は置く前に見える
- 一時停止と倍速がある
- 機械の形は四角だけ（Celestial Alchemy と遊びが似るので、いびつにしない）
- 量の積み増しだけの章を作らない。依頼の量は、そのときの解放で作れる範囲にする
- お金は入れない。素材を貯めて払う研究ツリーは作らない
- 遊ぶのは PC（マウス）。スマホには対応しない

## 決まった仕組み（11/16）

| 項目 | 決めたこと |
|---|---|
| 題材 | ファンタジーの魔導具の工房。エーテルなどの架空の素材。Celestial Alchemy で使った名前は避ける |
| 盤面 | 区画式。町の地図に区画が並び、1章で1区画（画面1枚、真上から）。前の区画は動き続け、作った物を共通倉庫へ送る |
| 量の測り方 | 毎分の量。「毎分○個を1分流す」で達成（一旦。試作を触って見直す）。前の区画が毎分出せる量が、次の区画で使える量 |
| 開き方 | 依頼に一本化。報酬の欄に開く物（機械・別レシピ・物流の道具・次の区画）を書く。依頼は常に1〜3件見せる |
| 魔力 | 魔力炉にベルトで燃料を入れると、範囲内の機械が動く。炉1つで動かせる台数に上限。足りないと止まらず、範囲内が全部遅くなる。区0〜2の機械は魔力なしで動く |
| 熱と冷気の源 | 竜炉や霜の柱も、魔力炉の範囲に入れないと動かない |
| 系統 | 機工（比率と組み立て）／炉と霜（通り道がレシピ）／エーテル（時間・副産物・あふれ）／育てる（増える素材）／総まとめ（飛空艇）。各系統の大目標は達成後も毎分流し続ける |
| 区画の組み方 | 1区画で新しく入るのは、制約か素材のルール1つと、物流の道具1つまで。1区画の中で組むのは2〜3段、中間の部品は3〜5個 |
| 長さ | 品目40〜50、16〜20区画、12〜15時間 |
| 最初に試す数字 | 1区画 20×14マス、範囲 5×5〜7×7、機械 1×1・2×2・3×3、1区画30〜60分 |

## 作り方

| 項目 | 決めたこと |
|---|---|
| 形 | 静的HTML＋JavaScript（ESモジュール）。ビルドなし。`index.html` を開けば動く（ローカルでは `npm run serve`、http://localhost:5191/） |
| 描画 | 盤面は canvas、依頼・パレット・メニューは HTML |
| シミュレーション | 決まった刻みで進め、描画と分ける。`src/core/` に置き、画面なしで動く。テストと道具が同じコードを使う |
| ベルト | 物を1個ずつ自由な位置で持たず、ベルトをひとつながりの列として扱う。素材が範囲のマスに入ったときだけ変化を判定する |
| 範囲 | 置いたとき・壊したときに計算し直して持っておく |
| 台数計算 | `tools/` に、レシピ表と目標の毎分の量から、必要な機械の台数と原料の量を出す道具を置く。依頼の量が無理でないかをここで確かめる |
| 納まるか | 各区画で依頼を満たす配置が実際にあることを、お手本の配置（テストで動かす）で守る。自動で探す仕組みは、試作のあとで考える |
| 保存と共有 | 盤面を JSON にして localStorage に保存。図面は文字列や URL で渡す |
| テスト | `npm test`（Node の標準テスト） |
| 公開 | GitHub Pages（main ブランチの一番上のフォルダ）。リポジトリは公開 |
| 進み具合 | GitHub の Milestones ＝ フェーズ、Issues ＝ やること・メモ。メモの Issue には作った時点でマイルストーンを付ける。フェーズを閉じる前に、残っている Issue を並べる |
| 言語 | 日本語だけ |

### フェーズ0で決めたこと（11/16 人が遊んで OK。固定）

| # | 決めること | 仮のルール | 気になる点 |
|---|---|---|---|
| 1 | ベルトの速さ | 1秒＝10刻み。1マスを5刻みで進み、1マスに1個。ベルト1本で毎分120個まで | 機械1台が毎分30個なので、ベルト1本で機械4台分 |
| 2 | 機械の入口と出口 | 機械に向きがある。正面の辺が出口、残りの3辺はどこからでも入る。機械どうしを直接つなげてもよい | 入口が3辺だと詰め込みが緩いかもしれない。きつくするなら「入口は後ろの辺だけ」 |
| 3 | 素材が変わるタイミング | 範囲の中にいた刻みの合計で変わる。鉱石は熱の中に15刻み（止まらずに3マス分）で溶ける | ベルトが詰まって範囲の中で止まっていても溶ける。範囲の角を2マスだけかすめると溶けない |
| 4 | 倉庫の口 | 「出す口」と「納める口」を分ける。出す口は出す素材を1つ選ぶ。位置は区画ごとに固定 | – |

ほかに仮で決めたこと：

- 合流は、ベルトを同じマスに向けるだけ。交互に通す
- 分岐（1マス）は後ろから受けて、正面・左・右のつながっている先に順番に出す。詰まった先は飛ばす
- 機械は、材料をレシピ2回分まで、できた物を2回分までためる。出口が詰まると止まる
- 機械の様子は working / waiting（材料待ち）/ blocked（出口が詰まり）/ no-field（範囲の外）で持つ（詰まりの原因を見せるため）
- 熱と冷気が重なったマスは打ち消し合う（仕組みだけ入れた。冷気の源はまだない）
- 範囲が要る機械は、全部のマスが範囲に入っていること

### 道具

- `npm test`：ルールのテスト（56個）。お手本の配置（`test/models.js`）で、はじめから順に全部の依頼を達成するところまで動かす
- `npm run calc -- plate=30 dust=30`：目標の毎分の量から、機械の台数・範囲を通すマス数・倉庫から出す量を出す

### フェーズ1の試作（11/16 人が遊んで OK）

**結果：** 通り道を選ぶ悩みは面白い／眺めて気持ちいい／詰まりの原因は見て分かる／操作の不満なし／仮のルール4つは「快適なので OK」（詰まって止まっていても溶ける、機械は3辺から入る、もこのまま）。ベルトを引いたあとの向きも、気にならないのでこのまま。

- 区0 工房の入口：木材 → 板。依頼は「板を毎分30個」（報酬：分岐）→「板を毎分90個」（報酬：区1）
- 区1 炉の間：鉱石 → 鉱石粉／熱を通して金属板。依頼は「鉱石粉を毎分30個」（報酬：竜炉と鋳型台）→「金属板を毎分30個」→「金属板60個と鉱石粉30個を同時に」。竜炉は1つまで
- 画面：置く・壊す・回す、ベルトをドラッグで引く、熱の範囲の表示、機械のランプ（材料待ち・出口づまり）、納めている毎分の量、一時停止と倍速、区画ごとの保存（localStorage）
- 動いているのは開いている区画だけ（前の区画が動き続けるのはフェーズ3）
- 見た目は仮（色と形だけ）。ベルト1本ごとの毎分の量の表示は、まだない

遊んで確かめること：

1. 通り道を選ぶ悩み（熱を通す・通さない）が面白いか
2. 眺めて気持ちいいか
3. 詰まりの原因が見て分かるか
4. 操作の不満（小さくてもすぐ言う）
5. 仮のルール4つ（特に「詰まって止まっていても溶ける」）はこのままでよいか

### フェーズ2の中身の表（11/17 人が全部 OK）

- 下書きのデータ：`src/data/content-draft.js`（素材22・機械14・道具4・8区画の依頼）。確かめる道具：`node tools/check-content.mjs`（依頼ごとの台数・魔力炉・面積の目安・倉庫の収支）
- 分かったこと：機械が占めるのはどの区画も広さの1〜6%で、今の広さ（20×14〜26×16）では詰め込みにならない。区画を小さくする案を出した
- 倉庫の収支：全区画が流し続けると金属板が毎分15、枠が毎分5足りない（前の区画を改善する理由。狙いどおり）
- 問い6つの答え：地脈・倉庫の口の量（入ってくる毎分の量まで、分け合うときは等分）・相乗と干渉の数字・金属板が熱で赤熱する・魔力炉の量（1台で4台、燃料毎分6）は案どおり
- 区画の広さ：小さくする（依頼を満たせる最小に近い広さ。目安は区0が10×8、区1が12×9、区6・7が16×12）。置けないマスは増やさない（理由のない穴は不快。残すのは倉庫の口・柱・水路など形に意味がある物）
- 瓦礫（案）：区画の縁の瓦礫を、依頼と同じ形（例：板を毎分30、1分）で片づけると置けるマスが増える。依頼は片づけなくても解けるように作る
- 瓦礫はフェーズ3（骨組み）で、前の区画が動き続ける仕組みと一緒に入れる（11/17 人が決定）
- 色の試し描き1回目：`palette.html`（https://stm28355-ux.github.io/aether-atelier/palette.html）。素材22個を16×16のドット（ベルトの上では32ドット）、機械14種を色の家族（木＝茶、金属＝灰、火＝赤、霜＝青、魔力＝紫・青緑）で描いた。魔力の範囲は塗らずにマスの四隅の紫の点（冷気の青と混ざるため）。絵は `src/ui/sprites.js`

### フェーズ3の骨組み（11/21 人が遊んで OK）

**結果：** 問題なし。難しさは今は感じないが、序盤なのでよい。瓦礫の片づけは条件が軽いかもしれない（案：別の区画で何かを達成したら片づく）。どちらも区画が増えてから、フェーズ8で見直す（Issue #1）。

やること：

1. **区画を小さくする**：区0は9×7、区1は12×7、区2は9×6（置ける広さ）。お手本の配置をテストで動かして、依頼が納まることを守る
2. **倉庫**：区画の「納める口」に入った物は倉庫へ。前の区画の物を出す口は、倉庫に入ってくる毎分の量を等分して受け取る（1つの口にためられるのは3個まで。貯めて一気に出せない）。受け取り手がいない分は「余り」
3. **前の区画が動き続ける**：開いた区画は全部、裏で同じ刻みで動く
4. **瓦礫**：区画の端に瓦礫。「板を毎分30、1分」のように、余りの流れで片づける。片づけると置けるマスになる
5. **町の地図**：区画の一覧（状態・毎分出している量・配置の小さな絵）と、倉庫の毎分の出入り
6. **図鑑**：作った物の名前と役目
7. **見た目**：素材は試し描きの絵（`src/ui/sprites.js`）、機械は色の家族
8. **中身**：区0〜2（区2は「下をくぐる」なしの仮。区2の道具はフェーズ4）。データは `src/data/content.js`（下書きから移す）

作ったもの：

- `src/core/game.js`：開いた区画を全部同じ刻みで動かす。倉庫（入る・使われる・余り）、依頼と解放、瓦礫の片づけ、保存。保存の鍵は `aether-atelier-v1`（試作の保存とは別）
- `src/data/content.js`：中身の表から作ったデータと図鑑の役目。区0〜2（区0は9×7、区1は12×7、区2は9×6＋それぞれ瓦礫2か所）
- 画面：町の地図（#/map、区画の小さな絵と出している量、倉庫の表）、区画（#/d/d0 など、受け取る口・瓦礫の欄）、図鑑（#/book、ベルトの上で見た物が載る）
- テスト22個。お手本の配置（test/game.test.js の MODEL）で、3区画の依頼が全部達成でき、倉庫の分け方と瓦礫が守られる
- ブラウザで区0→区1→区2を操作で組み、全部の依頼の達成、区2への受け渡し、瓦礫の片づけ、図鑑を確かめた

決めたこと（人が決めていない細かいこと）：

- 解放した機械は、どの区画でも使える（区1を開くと区0でも粉砕機が置ける）
- 受け取る口は1つにつき3個までためる。口の左下の黄色い点が、たまっている数

```
■必ず確認してほしいこと：遊びの柱にかかわる変更、全体に効く値の変更、2通りに読める指示
■残っているメモ：Issue 番号（フェーズの終わりに読み上げる）
■報告に入れてほしいこと：依頼ごとの必要な台数・区画の空き具合・使われない機械やレシピ

```
